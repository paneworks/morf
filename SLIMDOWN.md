# SLIMDOWN

The plan for the `slimdown` branch: one clear engine and one well-organized
library, with no backward compatibility to keep. The branch starts from
`develop` at `ef9c2dd9`. Every number below was measured on that commit on
2026-10-27.

The engine core stays: scene, layout, text, vector, image, paint, render,
runtime, the Lua VM, windowing and the host. The work is in three places:
- **the widget kit:** reset to one list, libadwaita's;
- **the Lua API:** one name per function, and nothing without a caller;
- **the library:** reorganized by what each part is, with one shell's code
  moved out.

---

## 0. Rules for the branch

1. **No compatibility.**
   - No aliases, no shims, no "older form" functions, no deprecation
     period.
   - A renamed thing is renamed everywhere in the same commit: library,
     examples, specs, Rust tests and docs.
2. **One name per thing.**
   - `require("morf.X")` returns `morf.X`, and `require("morf")` returns
     `morf`.
   - Nothing can be reached by two paths.
3. **Nothing without a caller.** A function, module or widget ships only if
   one of these calls it:
   - the library;
   - an example;
   - a spec of a real use (a spec that exists only to test the thing itself
     doesn't count).

   One exception: a member of a kept set stays. That means the inverse of a
   kept codec, a verb of a wrapped protocol object, or a control of a kept
   player.
4. **Widget names follow libadwaita and GTK 4.**
   - snake_case without the prefix: `AdwActionRow` becomes `action_row`,
     `GtkScale` becomes `scale`;
   - American spelling, as GTK has it (`color`);
   - a widget's variants are its Adwaita style classes (`suggested`,
     `flat`, `pill`…).
5. **The library holds what any shell could use.** One shell's design,
   personal dashboards and one demo's helper live with their user.
6. **The crates stay where they are.**
   - `tools/layers.py --strict` keeps passing.
   - Code is deleted or reorganized inside its crate, not moved between
     crates.
   - The one exception is the shared environment parser (§7.4), which goes
     into `morf-value`.
7. **Every step ends green:**
   - `make test` and `make clippy` pass;
   - `morf check` passes on every example.

   Commits are one per part of a step, with a conventional title only.

```
library/
  lib/
    kit/            widgets: the contract, the archetypes, the composites, the default skin
    theme/          colour schemes and shape policy a theme builds on
```

Each folder holds one kind of thing, and each module name says what it is.

## 5. Step 3: reset the kit

The contract stops being a 13-toolkit catalogue and becomes libadwaita plus
the GTK 4 widgets libadwaita styles. Each part of the kit lives in one
place, and it is themed one way: through skins.

### 5.1 The contract's new shape

`kit/contract.lua` has four sections and no `stage` gating.
`ADWAITA_PLAN.md` §1 then adds the coverage status.

```lua
M.tokens = { colors = { ... }, type = { ... }, shape = { ... }, motion = { ... } }
M.archetypes = {
  Press = { adw = "GtkButton", widgets = {
    { name = "button", adw = "GtkButton",
      variants = { "suggested", "destructive", "flat", "raised", "opaque", "pill", "circular", "osd" } },
    ...
  } },
  ...
}
M.display = { { name = "avatar", adw = "AdwAvatar" }, ... }
M.composites = { { name = "action_row", adw = "AdwActionRow", parts = { "Press" } }, ... }
M.shell = { ... }  -- §5.7
```

What goes away:
- `M.stage` and every `stage` field: the contract is the list, and
  coverage is ADWAITA's report.
- `M.functions` (§5.8).
- `M.base.accessible` and the rest of `M.base`: they move into
  `kit/control.lua`, which already owns them.

### 5.2 Tokens

A theme defines these, and nothing else is required of it outside the
widgets.

- **colors:** libadwaita's named colours, in snake_case without `_color`:
  - accent, destructive, success, warning, error: each as `bg`, `fg` and
    standalone;
  - window, view, headerbar, sidebar, secondary_sidebar, card, dialog,
    popover, thumbnail: each as `bg` and `fg`;
  - the shade and border colours that go with them, `shade` and
    `scrollbar_outline`.

  Step 3 reads the full set from the libadwaita reference and writes it
  into `M.tokens.colors`.
- **type:** title_1 to title_4, heading, body, caption_heading, caption,
  monospace, numeric.
- **shape:** window, dialog, card, button and popover radii; border and dim
  opacities; focus ring width.
- **motion:** libadwaita's spring presets and the Easing set by Adw name.
  These replace the kit functions `spring`, `elastic`, `bud`, `ride` and
  `STRETCH`.

  - `on_reload(fn(ok, err))` takes a failure only when a handler returns
    true, so a handler that only cares about successes does not hide the
    error band.
  - `socket.open` and `socket.connect` are both kept: `open` is a polled
    view (`receive` with a timeout), `connect` delivers by callback over a
    unix socket or TCP.
  - `json.null` is kept: three library modules use it.
  - The root names §6.2 does not list but configurations use stay where
    they are: `version`, `process_id`, `options`, `operands`, `screens`,
    `windows`, `surface` and `prefers`.
  - `morf.archive`, `morf.workspace`, `morf.workspaces` and `morf.gamma`
    go in step 5 with their engine code (§7.1, §7.2).
  - What only the deleted functions used goes with them: the unlock
    request behind `pam.authenticate_unlock` (a lock screen unlocks by
    clearing `morf.surface.session_lock`), the clipboard callbacks behind
    `clipboard.subscribe`, the watch-files toggle behind `watch_files`,
    morf-kit's `tokens.rs`, morf-io's `streams.rs`, and the clock-format
    parsing in `morf-runtime`.
  - `ui.smoothed` goes; the `smoothed` behavior kind stays
    (`{ kind = "smoothed", ... }`).
  - `api/` keeps its grouping by theme: each binding registers into its
    namespace through `api/namespace.rs`. Splitting the files one module
    per namespace (§6.4) moves most of the 23,000 lines and changes no
    behaviour; it is left for after the branch.
  - Platform code only a deleted binding called (`quantize_colors`,
    `XkbKeymap::compile`, `VirtualList`, the fs path-part helpers) goes in
    step 5 with the other engine edges.
- **Step 5:**
  - `VirtualList` stays: `ui.ListView` is built on it.
  - `MORF_HDR_WHITE`, which §7.4 leaves out, joins `MORF_HDR` as
    `white=<n>` (`MORF_HDR=pq,white=300`).
  - `MORF_FRAME_LOG=2` (a frame's detail) becomes
    `MORF_PROFILE=frame_split` on the host's side and `render_split` on the
    renderer's, each taking the threshold that `MORF_FRAME_SPLIT_MS` and
    `MORF_RENDER_SPLIT_MS` gave: `MORF_PROFILE=frame_split=0`.
  - The plain variables are read through `morf_value::env::var`, `path`
    and `paths`, so no crate reads the environment itself; the desktop
    layer smoke example's `MORF_OUTPUT` stays a direct read.
  - The environment variables a configuration reads itself
    (`MORF_KIT_VARIANT`, the demos' switches) are not the engine's and stay.
